비개발자를 위한 핵심 인증 용어 1분 정리

PAT (Personal Access Token)
아이디/비밀번호 대신 사용하는 '컴퓨터 전용 신분증'입니다. 안티그래비티 CLI가 내 GitHub 계정을 대신해서 소스코드를 저장소에 올릴 때 사용합니다.
예시: ghp_a1b2c3d4e5...
Anon Key vs Service Role Key
Supabase 데이터베이스에 들어갈 수 있는 '출입증'입니다.
· Anon Key (Publishable): 손님용 (브라우저에서 사용해도 안전)
· Service Role Key (Secret): 마스터키 (절대 공개 금지)
사용위치: .env.local
.env 파일 (환경변수 보관함)
비밀키나 서버 주소(URL)를 코드 안에 직접 적지 않고, '비밀 자금성 금고'처럼 텍스트 파일에 따로 모아두는 곳입니다.
파일명: .env.local

Phase 2: Supabase DB 구축을 위한 SQL 전문 수록 (`test_inventory_schema.sql`)

sql
-- 1. test_inventory_items 테이블 생성
CREATE TABLE IF NOT EXISTS test_inventory_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    item_code VARCHAR(50) UNIQUE NOT NULL,
    name VARCHAR(250) NOT NULL,
    category VARCHAR(100) NOT NULL,
    location VARCHAR(100) DEFAULT '창고 A-1',
    stock_quantity INT DEFAULT 0 CHECK (stock_quantity >= 0),
    safety_stock INT DEFAULT 10,
    unit_price NUMERIC(12, 2) DEFAULT 0,
    status VARCHAR(50) DEFAULT '정상',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. test_inventory_transactions 입출고 내역 테이블 생성
CREATE TABLE IF NOT EXISTS test_inventory_transactions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    item_id UUID REFERENCES test_inventory_items(id) ON DELETE CASCADE,
    transaction_type VARCHAR(20) NOT NULL CHECK (transaction_type IN ('INBOUND', 'OUTBOUND')),
    quantity INT NOT NULL CHECK (quantity > 0),
    notes TEXT,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. Row Level Security(RLS) 정책 활성화 및 공개 읽기/쓰기 허용
ALTER TABLE test_inventory_items ENABLE ROW LEVEL SECURITY;
ALTER TABLE test_inventory_transactions ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Allow public read access" ON test_inventory_items FOR SELECT USING (true);
CREATE POLICY "Allow public insert access" ON test_inventory_items FOR INSERT WITH CHECK (true);
CREATE POLICY "Allow public update access" ON test_inventory_items FOR UPDATE USING (true);
CREATE POLICY "Allow public delete access" ON test_inventory_items FOR DELETE USING (true);

CREATE POLICY "Allow public transaction read" ON test_inventory_transactions FOR SELECT USING (true);
CREATE POLICY "Allow public transaction insert" ON test_inventory_transactions FOR INSERT WITH CHECK (true);

초보자가 반드시 겪는 트러블슈팅 Top 5 & 자가 진단표

[에러 1] GitHub Push 시 비밀 키 차단
Push cannot contain secrets 오류로 git push가 실패하는 현상입니다.
원인: .env에 비밀 키(Access Token)를 올리려고 함
해결: .gitignore에 .env.local을 추가하여 제외시킴
[에러 2] Cloudflare 새로고침 시 404
Cloudflare Pages 서브페이지 새로고침 시 404 Not Found가 발생하는 현상입니다.
원인: SPA(Single Page App) 라우팅 미설정
해결: public/_redirects 생성 후 /* /index.html 200 입력
[에러 3] Supabase PGRST205 에러
Could not find table in schema cache 메시지가 뜨는 현상입니다.
원인: SQL 스크립트를 데이터베이스에서 실행하지 않음
해결: Supabase SQL Editor에서 test_inventory_schema.sql 실행
[에러 4] Project does not exist
Wrangler 배포 시 Pages 프로젝트를 찾지 못하는 현상입니다.
원인: 최초 1회 배포 프로젝트 미생성
해결: npx wrangler pages project create vibe-inventory 실행
[에러 5] index.html 파일 안 열림
HTML 더블클릭 시 화면이 하얗게 나오거나 작동하지 않는 현상입니다.
원인: 브라우저 CORS/모듈 보안 정책 (file:// 접속 차단)
해결: 단일 스탠드얼론 HTML 사용 또는 npm run dev 실행

함수처럼 쓰는 바이브 코딩 프롬프트 템플릿 모음 (6대 재사용 `@fn_...`)

[함수 1] @fn_create_app(앱이름, 주요기능, 디자인)
@fn_create_app - 앱이름: [예: 실시간 주문 관리 시스템] - 주요기능: [1. 주문 목록 및 상태 변경 대시보드, 2. 신규 주문 등록 Modal, 3. 실시간 필터링] - 디자인스타일: [다크 테마, Tailwind CSS, Lucide Icons] 터미널 명령어를 직접 실행해서 프로젝트 세팅과 패키지 설치까지 한 번에 완료해줘!
[함수 2] @fn_connect_supabase(프로젝트REF, 테이블목록, 실시간구독)
@fn_connect_supabase - 프로젝트REF: [예: apwjwaryrlpqmdabilvu] - 테이블목록: [1. orders (주문), 2. order_items (주문상세)] - RLS보안정책: [공개 익명 읽기/쓰기 허용] - 실시간구독: [Realtime postgres_changes 활성화] `schema.sql` 스크립트를 작성하고, .env.local 연동과 Supabase SDK 연결 코드(App.jsx)까지 모두 완성해줘!
[함수 3] @fn_deploy_cloudflare(프로젝트명, 빌드검증)
@fn_deploy_cloudflare - 프로젝트명: [예: vibe-orders] - 빌드검증: [npm run build 실행 및 에러 자가 수정] - 배포명령: [npx wrangler pages deploy ./dist --project-name=vibe-orders] 프로덕션 배포 완료 후 최종 라이브 접속 URL을 출력해줘!
[함수 4] @fn_natural_db_alter(테이블명, 변경내용)
@fn_natural_db_alter - 대상테이블: [예: test_inventory_items] - 변경내용: [brand 문자열 컬럼 추가하고 기본값 'Antigravity'로 설정해줘] Supabase CLI 및 SDK 연동 코드까지 일괄 업데이트해줘!
[함수 5] @fn_auto_debug(에러로그, 발생상황)
@fn_auto_debug - 에러로그: [예: PGRST205 Could not find table in schema cache] - 발생상황: [Supabase 연동 후 데이터 불러올 때 발생] 원인을 분석하고 코드 또는 SQL 스크립트를 자가 치유 수정해줘!
[함수 6] @fn_github_sync(저장소명, 커밋메시지)
@fn_github_sync - 저장소명: [예: joseki-korea/agy-vibe-coding] - 커밋메시지: [feat: update interactive chart components] .env.local 비밀키 차단 확인 후 Git Commit & Push를 완결해줘!

바이브 코딩 개발자를 위한 GitHub 저장소 관리 5대 원칙

원칙 1 보안 유출 방지 (Secret Protection)

Supabase Access Token(`sbp_...`)이나 API Key는 .env.local에 보관하고 .gitignore에 추가하여 GitHub에 유출되지 않도록 차단합니다.

원칙 2 시각적 커밋 라벨링 (Conventional Commits)
· feat: 신규 기능 구현 (예: feat: add stock movement modal)
· fix: 버그 자가 치유 수정 (예: fix: resolve 404 routing issue)
· docs: 매뉴얼 및 문서 업데이트 (예: docs: update vibe manual v16.0)

최종 기능 및 보안 점검 체크리스트

[ ] 재고 목록 조회, 검색, 카테고리 필터링이 잘 작동한다.
[ ] 제품 추가 및 입출고 변경 결과가 Supabase DB에 실시간 저장된다.
[ ] 브라우저를 새로고침해도 데이터가 유실되지 않고 유지된다.
[ ] RLS 보안 정책이 활성화되어 있고 마스터키(Secret Key)가 코드에 포함되지 않았다.
[ ] `.env.local` 파일이 `.gitignore`에 등록되어 GitHub에 유출되지 않았다.
[ ] Cloudflare Pages 라이브 주소가 PC 및 모바일 브라우저에서 잘 열린다.
[ ] 서브페이지를 새로고침해도 404 Not Found 에러가 발생하지 않는다 (`public/_redirects`).

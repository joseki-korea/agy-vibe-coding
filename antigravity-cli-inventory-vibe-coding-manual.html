핵심 인증 용어 및 2026년 기준 Key 안내

PAT (Personal Access Token)
아이디/비밀번호 대신 사용하는 '컴퓨터 전용 인증 키'입니다. CLI가 내 계정을 대신해서 소스코드를 올릴 때 사용합니다.
예시: ghp_a1b2c3d4e5...
Publishable Key vs Service Role Key
Supabase 데이터베이스 접속 키 종류입니다.
· Publishable Key (`sb_publishable_...`): 브라우저용 (권장)
· Anon Key: 기존 프로젝트용 Legacy 키
· Secret / Service Role Key: 서버 전용 (브라우저 사용 금지)
보관위치: .env.local
.env.local (환경변수 보관함)
비밀키나 서버 주소(URL)를 소스코드에 직접 적지 않고 텍스트 파일로 안전하게 분리해두는 설정 파일입니다.
파일명: .env.local

MCP (Model Context Protocol) 연동 및 자연어 DB 제어 규칙

MCP 기본 연동 4단계 규칙

1. OAuth 인증 & 토큰 설정: Supabase Access Token(`sbp_...`) 연결
2. 대상 프로젝트 지정: mcp.json에 target project ref 설정
3. 안전 읽기 우선 (`read_only=true`): 조회 작업 시 기본적으로 읽기 전용 옵션을 사용
4. 수정·삭제 승인 규칙: 데이터베이스 구조 변경(ALTER, DROP) 전에는 반드시 사용자의 사전 승인을 받음
자연어 DB 제어 프롬프트 예시
· 💬 "test_inventory_items 테이블의 스키마 구조를 조회해줘" · 💬 "brand 컬럼 추가 전 변경 SQL을 보여주고 승인을 요청해줘"

Phase 2: 안전한 Supabase DB 구축을 위한 SQL 스크립트 (`test_inventory_schema.sql`)

sql
-- 1. test_inventory_items 테이블 생성
CREATE TABLE IF NOT EXISTS test_inventory_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    item_code VARCHAR(50) UNIQUE NOT NULL,
    name VARCHAR(250) NOT NULL,
    category VARCHAR(100) NOT NULL,
    location VARCHAR(100) DEFAULT '창고 A-1',
    stock_quantity INT DEFAULT 0 CHECK (stock_quantity >= 0),
    safety_stock INT DEFAULT 10,
    unit_price NUMERIC(12, 2) DEFAULT 0,
    status VARCHAR(50) DEFAULT '정상',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Row Level Security(RLS) 정책 활성화 및 권한 분리
ALTER TABLE test_inventory_items ENABLE ROW LEVEL SECURITY;

-- [보안 정책] 비로그인 사용자: 읽기(SELECT) 전용 허용
CREATE POLICY "Allow public read-only access" ON test_inventory_items 
    FOR SELECT USING (true);

-- [보안 정책] 인증된 사용자/관리자: 추가 및 수정 허용
CREATE POLICY "Allow authenticated insert" ON test_inventory_items 
    FOR INSERT WITH CHECK (auth.role() = 'authenticated');

CREATE POLICY "Allow authenticated update" ON test_inventory_items 
    FOR UPDATE USING (auth.role() = 'authenticated');

초보자가 자주 겪는 트러블슈팅 Top 5

[오류 1] GitHub Push 시 비밀 키 차단
Push cannot contain secrets 오류로 push가 안 되는 현상입니다.
원인: .env에 비밀 키를 포함시킴
해결: .gitignore에 .env.local 추가 후 차단
[오류 2] Cloudflare 새로고침 시 404
서브페이지 새로고침 시 404 Not Found가 발생하는 현상입니다.
원인: SPA 싱글 페이지 라우팅 미설정
해결: public/_redirects에 /* /index.html 200 입력
[오류 3] Supabase PGRST205 오류
Could not find table in schema cache 메시지가 발생할 때입니다.
원인: SQL 스크립트 미실행
해결: Supabase SQL Editor에서 스키마 실행
[오류 4] Project does not exist
Wrangler 배포 시 프로젝트를 찾지 못하는 현상입니다.
원인: 최초 1회 프로젝트 미생성
해결: npx wrangler pages project create vibe-inventory 실행
[오류 5] index.html 파일 실행 불가
더블클릭 시 화면이 작동하지 않는 현상입니다.
원인: 브라우저 보안 정책 (`file://` 모듈 차단)
해결: 로컬 웹서버 실행(`npm run dev`)

GitHub 저장소 관리 5대 원칙 및 최종 점검 체크리스트

원칙 1. 비밀 정보 유출 방지
비밀키나 토큰은 .env.local에 보관하고 .gitignore에 추가하여 유출을 차단합니다.
원칙 2. Conventional Commits 사용
feat:(기능), fix:(수정), docs:(문서) 접두어를 사용해 명확히 기록합니다.
원칙 3. 기능별 브랜치 사용
새 기능 개발 시 메인 브랜치 직접 수정 대신 feature 브랜치를 활용합니다.
원칙 4. Pull Request 코드 검수
메인 브랜치 병합 전 PR(Pull Request)을 통해 변경 사항을 검토합니다.
원칙 5. 배포 전 빌드 검증
npm run build를 사전에 실행하여 문법 및 빌드 오류가 없는지 확인합니다.
